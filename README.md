# QArm Fruit Sorting System

**Autonomous, teleoperated and voice-controlled fruit sorting** with a **Quanser QArm 4-DOF robot** and its arm-mounted **Intel RealSense D415 RGB-D camera**. Classical computer vision and analytical kinematics in Python, wrapped in a thin Simulink facade.

## Overview

The system sorts **14 fruits** (6 strawberries, 3 bananas, 5 tomatoes) into 3 baskets. It was demonstrated live on real hardware on 1 May 2026: the full 14-fruit autonomous cycle, manual teleoperation and voice control all ran as designed.

Three operating modes:

- **Autonomous mode** (`main_final.py`): move to a fixed survey pose, capture RGB-D, self-check calibration against a chessboard, detect fruits (HSV + shape), project to base frame, then run the pick-and-place state machine per fruit category, or for all fruits in sequence.
- **Remote mode** (`main_gui.py`): Tkinter operator GUI with live D415 feed, Cartesian jog, basket shortcuts, gripper control, emergency stop, and a Manual / Auto switch.
- **Voice control** (`voice_control.py`, optional): offline Vosk recogniser with a wake-word protocol, integrated into the GUI. Say `robot`, then a command within 2 s: `strawberry`, `banana`, `tomato`, `all`, `home`, `refresh`, `survey`. `stop` is always accepted, no wake word needed.

No machine learning is used anywhere in the pipeline. Every stage is explainable and tunable by hand.

## Architecture

```
+-------------------+       py.* bridge        +------------------+
|   Simulink        |  <-------------------->  |   Python Core    |
|   Facade          |   coder.extrinsic()      |                  |
|                   |                           |  Kinematics      |
|  MATLAB Function  |                           |  Vision          |
|  blocks calling   |                           |  Trajectory      |
|  Python modules   |                           |  Controller FSM  |
|                   |                           |  Hardware Driver  |
+-------------------+                           +--------+---------+
                                                         |
                                                   Quanser SDK
                                                   (USB HIL)
                                                         |
                                               +---------+---------+
                                               |   QArm Hardware   |
                                               |   + D415 Camera   |
                                               +-------------------+
```

**Design principle:** *Simulink is the facade, Python does the real work.* All algorithms are implemented in Python/NumPy with the Quanser SDK for hardware I/O. The Simulink layer wraps Python via `py.*` calls inside MATLAB Function blocks (in-process `pyenv`, single address space). No QUARC is required.

### Pipeline

1. **Session calibration** (`calibrate_chessboard.py`, under 30 s): print the 7x5 chessboard (30 mm squares, `figures/chessboard_7x5_30mm.png`), jog-touch its origin corner to get `chess_origin_in_base_m`, move to the `survey1` pose, `findChessboardCorners` + `solvePnP` for the camera extrinsics at that pose, then a ray-plane / homography model for pixel-to-table projection. Output: `session_cal.json`. Residual gate: warn above 3 mm, error above 10 mm. The launcher warns if the file is older than 12 h.
2. **Survey capture** (`survey_capture.py`): move to `survey1`, wait for the joint PID to settle, capture, re-check chessboard residual, run detection.
3. **Detection** (`fruit_detector.py`): HSV masks per fruit with hue-wrap for red, morphological cleanup, contour area and circularity gates, green-calyx test to separate strawberry from tomato, widest inscribed disk as grasp point, depth lookup and projection to base-frame XYZ.
4. **Pick and place** (`sorting_controller.py`, `pick_single.py`): 13-state FSM, analytical IK with Newton-Raphson refinement, quintic joint trajectories, gripper close with settle-and-readback so the jaw adapts to fruit size.

**Why a fixed survey pose:** the D415 is mounted on the QArm wrist, so camera extrinsics change with every joint configuration. Detection therefore always happens from `survey1`, and the calibration is solved for that pose.

## Python Core Modules

| Module | Purpose | Key feature |
|--------|---------|-------------|
| `qarm_driver.py` | Hardware I/O wrapper | Atomic joint+gripper read/write via Quanser HIL, joint-limit clamping, safe `home()` with PID settle |
| `qarm_kinematics.py` | FK + IK (4-DOF) | Analytical IK (4 solutions) + Newton-Raphson refinement. Max round-trip error: **0.0002 mm** |
| `trajectory.py` | Motion planning | Quintic rest-to-rest splines (zero velocity and acceleration at both ends), cubic fallback, multi-segment chaining |
| `fruit_detector.py` | HSV + shape classifier | Strawberry / tomato / banana, calyx detection, base-frame projection |
| `camera.py` | D415 RGB-D capture | Quanser Video3D wrapper, auto-exposure |
| `session_cal.py` | Calibration data carrier | Loads and validates `session_cal.json` |
| `calibrate_chessboard.py` | Session calibration CLI | Chessboard + solvePnP extrinsics at the survey pose |
| `survey_capture.py` | Survey orchestration | Move, settle, capture, self-check, detect |
| `sorting_controller.py` | 13-state FSM | INIT -> GO_HOME -> SCAN -> SELECT_FRUIT -> APPROACH -> DESCEND -> CLOSE_GRIPPER -> ASCEND_PICK -> MOVE_TO_BASKET -> DESCEND_PLACE -> OPEN_GRIPPER -> ASCEND_PLACE -> DONE |
| `sorting_controller_sim.py` | dt-driven FSM twin | Same logic without wall-clock time, exports integer `state_id` for Simulink logging |
| `pick_single.py` | Single pick cycle | One fruit, with per-fruit depth and X-bias tuning |
| `picker_viewer.py` | Autonomous operator loop | OpenCV window with detection overlay and category-batch keys |
| `voice_control.py` | Voice commands | Vosk + PyAudio, restricted grammar, wake-word state machine |
| `trace_logger.py` | Crash-safe event log | Line-buffered trace of every command, state change and error |
| `preflight.py` | Pre-session checks | QArm round trip, D415 warmup, calibration freshness |

Entry points: `main_final.py` (autonomous picker), `main_gui.py` (GUI + voice), `main_remote.py` (keyboard teleop), `teach_points.py` (teach pendant), `camera_preview.py` (live viewer).

Legacy and diagnostic scripts (`calibrate_hand_eye.py`, `calibrate_closed_loop.py`, `ugreen_*.py`, `diag_*.py`, `analyze_*.py`) are kept for reference. They document earlier calibration approaches (Umeyama hand-eye, external floor camera) that were superseded by the chessboard session calibration.

## Tools

### Teach Pendant (`teach_points.py`)

Interactive jog tool with live D415 view for recording workspace waypoints (`survey1`, baskets, home poses) to `teach_points.json`:

- Real-time keyboard jog via OpenCV window (arrows for XY, r/f for Z, q/e for wrist, SPACE for gripper)
- Save / load / goto named poses; automated test routine across saved points
- Gripper safety: capped close / open commands (`GRIP_CLOSE_CMD=0.65`, `GRIP_OPEN_CMD=0.10`) prevent servo overload, with position readback after every gripper operation
- Trace logger: every event written to `logs/robot_trace_*.log`

### Autonomous picker (`main_final.py`)

Keys in the picker window: `b` / `t` / `s` sort one category (banana / tomato / strawberry), `m` runs all three in sequence, `r` re-captures, `ESC` quits. `--dry-run` exercises the pipeline without commanding the arm.

### Camera Preview (`camera_preview.py`)

Live D415 viewer showing color + depth side by side with FPS counter. Press `s` to save snapshots.

## Quick Start

### Requirements

```bash
# Python packages (use Python 3.13: the Quanser SDK wheels are version-specific)
C:\Python313\python.exe -m pip install numpy opencv-python pillow

# Optional, voice control
C:\Python313\python.exe -m pip install vosk pyaudio
# Download vosk-model-small-en-us-0.15 from https://alphacephei.com/vosk/models
# and unzip it to models/vosk-model-small-en-us-0.15 (folder is git-ignored)

# Quanser SDK wheels (run from the SDK installer directory)
cd "C:\Program Files\Quanser\Quanser SDK\python"
install_quanser_python_api.bat
```

### Verify the environment (no robot needed)

```bash
cd python
C:\Python313\python.exe validate_python.py
# Expected: FK/IK, Trajectory, Detection, Controller all PASS
```

### Lab session

```bash
# 1. Sanity checks: QArm, D415, calibration freshness
C:\Python313\python.exe python/preflight.py

# 2. Session calibration (once per session, or after the base is moved)

C:\Python313\python.exe python/main_gui.py

run_FruitSorting      % simulation mode

```

## Safety Features

- **Gripper overload prevention**: close commands capped at 0.65, open at 0.10. After every gripper operation the actual position is read back so subsequent commands match reality.
- **No idle command spamming**: the QArm position-mode PID holds setpoints autonomously; the control loop does not resend commands when idle.
- **Joint limit clamping**: all IK solutions are clamped to per-axis limits before being sent to hardware.
- **Workspace box and Z-height safeguards**: approach and transit heights prevent table collisions; remote jog is clamped to a fixed workspace box.
- **Emergency stop**: latching e-stop in both the Tkinter GUI and the Simulink remote HMI; `stop` voice command bypasses the wake word.
- **Crash-safe trace logging**: every command, state change and error is logged line-buffered to disk.
